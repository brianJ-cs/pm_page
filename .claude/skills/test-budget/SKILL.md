# 長測試的預算

**使用者的原話（2026-09-29）：「this amount of time taken is simply unacceptable」。**
那一輪真正修東西的時間不到三成，其他全是：跑一趟 5～10 分鐘 → 在第 N 步失敗 → 改測試 → 從頭再跑。
下面每一條都對應一次真的浪費掉的時間。

## 0. 動手前：講預算、看有沒有人同時在改

- **先講要花多久**，超過就停下來回報，不要默默再跑一輪。
  一個故事（一段流程）在瀏覽器裡 ≤ 3 分鐘；全套只在最後跑**一次**。
- **看檔案是不是別人正在改**：`ls -la --time-style=+%H:%M:%S design_and_PM.html`，隔一陣子再看一次。
  那一輪有另一個 session 同時在改 `design_and_PM.html` 和 `review-flow.mjs`（加了「審核」分頁、把刷子搬到左邊的印章），
  測試一直在追一個會動的目標 —— 三輪全套是因為 UI 被換掉才失敗的。
  **看到時間戳在動（或 Edit 回「file modified on disk」）就停下來問使用者**，不要自己去適應。

## 1. 便宜的先跑，貴的最後跑一次

| 順序 | 跑什麼 | 多久 | 什麼時候跑 |
|---|---|---|---|
| 1 | `node demo/review/rules.test.mjs`（規則） | 1 秒 | 每改一次規則就跑 |
| 2 | 只開頁面、看 console（run-pm-page 第 1 級） | 4 秒 | 改完主程式先跑這個 |
| 3 | **一個故事**的瀏覽器腳本（從快轉到那一關開始） | 1～3 分鐘 | 每個故事各自先綠 |
| 4 | 全套（review-flow.mjs、自己寫的多故事腳本） | 6～10 分鐘 | **全部故事都綠了才跑一次** |

- **規則能測的就在規則裡測**：「標了不算送出」「全部送出主管才開始」這種，rules.test.mjs 一秒就知道，
  不要靠瀏覽器走十分鐘去證明。瀏覽器只驗「畫面上看得到、按得到」。
- **絕不在全套腳本裡除錯。** 全套在第 N 步失敗 → 立刻切出「前置 ＋ 第 N 步」的小腳本（見第 3 節），
  在小腳本上修到綠，再回全套。那一輪有四次是「改一行 → 全套從頭十分鐘 → 下一步又失敗」。

## 2. 一次只開一個 Chrome

同時跑三支 driver（全套 ＋ 兩個情境）→ `CDP 等了 60 秒沒回應：Runtime.evaluate`，整支卡死、白跑一趟。
**一次一支**。要平行就只平行「純 node」的東西（規則測試）。

## 3. 失敗了怎麼縮小

- 腳本一律**每一步印一行**（`[n/N] ✓/✗ 說明 = 拿到的值`），拿到的值要印出來 —— 只印 ✓／✗ 的話還得再跑一次才知道拿到什麼。
- 小腳本的做法：拿長腳本的「幫手」那一段，接上「快轉到那一關 → 那一步 → 讀數 ＋ 截圖」。
  **用 🛠 快轉直接到那一關**，不要從提明細一路點過去。
- 「按不到」（`no visible element`／`nothing containing`）**先截圖再改**。那一輪的「按不到」全是被東西蓋住或藏起來，沒有一次是程式壞了，
  但每一次都是先猜、改、再跑十分鐘才知道猜錯。

## 5. 測試本身的坑（都是那一輪真的踩到的）

- **`ENAMETOOLONG`**：driver 的參數（一長串 `--eval`）超過 Windows 命令列上限。
  參數寫進 JSON 檔，用 `drive-from-file.mjs`（同一個資料夾）交給 driver。
- **預期寫錯＝白跑一趟**。寫檢查之前先確認規則：例如蓋章後的課長要等「他管的**每一格**（跨版位）」都蓋完才開始 ——
  只送一塊的話課長那邊本來就不會有待辦。不確定就先在 rules.test.mjs 裡問一次（1 秒）。
- **不要寫死會變的字**：「蓋章 2，送回…」第二次退件就變「蓋章 3」。用不會變的那一段（「送回退件的人」）。
- **toast 會消失**：要驗 toast 就在動作後 1 秒內讀，不然改讀畫面上留得住的東西。
- **快轉不一定推得動**：快轉只往前推；有「還沒補完一校」的格子時它要替 PM 按「補完一校」（2026-09-29 已補）。
  版位卡住的時候先看快轉那一頁亮在哪一關，不要以為是自己的功能壞了。

## 6. 改檔、shell（edit-fast 那一份講過，這一輪又犯了）

- **行尾不要相信 Git Bash 的 `grep -c $'\r$'`**（它看不到 CR，回 0）。要用 node 數：
  `design_and_PM.html`、`CLAUDE.md` 是 **CRLF**；`review-rules.js`、`review-store.js`、`review-flow.mjs`、`rules.test.mjs`、`review-test-later.md` 是 LF。
  錨點對不到的第一個懷疑就是行尾。
- **不要在 shell 裡寫 JS**（`node -e`、`bash -c` 裡的反引號）—— 那一輪又炸了一次 command substitution。一律 Write 一支 .mjs。
- **`cat > 檔案` 沒有接 heredoc 會等 stdin 等到逾時**（卡了 120 秒）。

## 7. 等待

- 超過 2 分鐘的跑背景，**跑完會通知**，不要用 `timeout 590 bash -c 'until …; do sleep 15; done'` 一次卡十分鐘。
- 背景在跑的時候照樣回報進度（跑到第幾步、目前有沒有紅），使用者不該要問才知道。
- **同一個測試因為「測試自己的問題」失敗兩次，就停下來回報**，列出剩下哪幾步還沒驗，讓使用者決定要不要繼續 ——
  不要進第三輪。

## 那一輪的帳（留著當對照）

修的東西：5 個審核的 bug、1 個 IndexedDB 的舊 bug、印章改成「標起來 → 按送出」、印章搬進審核分頁。規則 237 項、真的人走一遍 39＋19 項都綠。
浪費掉的：UI 被另一個 session 換掉（3 輪全套）、蓋住的東西（浮層、確認框、分頁沒翻開，5 輪）、
三個 Chrome 一起跑卡死（2 輪）、命令列太長、行尾、shell 裡寫 JS、預期寫錯（各 1 輪）。
