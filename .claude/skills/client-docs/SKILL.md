# 交出去的文件

這個專案是一個人在做。寫給外面的文件最常出兩種錯，兩種都不是文筆問題：

1. **承諾了一個沒有機制撐著的東西**（自動回覆、可用率 99%、月報 KPI）——
   簽下去就要養一套系統，而養它的人就是要維護 DM 系統的同一個人。
2. **把寫給自己的旁白印在交出去的那一頁上**（「與其寫上去再違約」「這條要保留，
   不然對方會…」）——讀的人會看到你的底牌。

下面兩節分別處理這兩件事。

## 一、每寫一條承諾，先問「這靠什麼成立」

寫下任何數字或承諾之前，問一次：**這件事發生的時候，誰會知道？用什麼證明？**

答不出來就不要寫。實際的判準：

| 想寫的東西 | 靠什麼成立 | 一個人做得到嗎 |
|---|---|---|
| 回應時間 | 信箱的收信／回信時間戳 | ✅ 零建置，信箱本來就在 |
| 逾時幾次 | 同上，用數的 | ✅ |
| 版本回滾 30 分鐘 | 代管平台本來就有的功能 | ✅ 但**要先實際演練一次並計時** |
| 自動回覆受理編號 | 表單＋腳本＋工單系統 | ❌ 砍掉，改成「信件即紀錄」 |
| 可用率 99% | 全天候外部監測＋月報表 | ❌ 砍掉，或變成加購項目 |
| 達成率 90%＋費用抵減 | 逐案統計 | ❌ 改成「逾時次數」 |
| 月報（案件數／分布／KPI） | 每月整理 | ❌ 改成一封摘要信 |

**做不到的東西不是刪掉就算了，要換成一個做得到、而且講得出道理的替代品。**
「不承諾可用率」聽起來像退讓，寫成「沒有人在量的數字在爭議時誰都拿不出證據，
要的話可以另建監測、月費另計」就變成一個選項——義務變成加購。

⚠️ **最危險的是聽起來很專業的那幾項**。月報、KPI、季檢討會、工單系統，
寫進去顯得有規模，而維護它們的成本全部落在同一個人身上，
最後的結果是真正該做的事（修問題）被報告排擠掉。

## 二、一份文件寫成兩份

**客戶版**（交出去，輸出 PDF）只放規範一件事的句子。
**註記版**（`<文件名>-註記.md`，不對外）放所有理由、底線、待辦。

判斷一句話屬於哪一份，問：**它在規範一件事，還是在評論這份文件？**

| 這一句 | 去哪 |
|---|---|
| 「P1 於服務時段內 2 小時回信」 | 客戶版 —— 規範 |
| 「回應與修復是兩件事，修復時間取決於根因」 | 客戶版 —— 解釋條款，讀的人需要 |
| 「這一節是 2 小時能被接受的真正理由」 | **註記版** —— 評論文件 |
| 「第 7 點務必保留，不然對方會…」 | **註記版** —— 底牌 |
| 「與其寫上去再違約」 | **註記版** —— 交出去等於承認會違約 |

註記版至少要有：**各節為什麼這樣寫**、**談判時哪些能讓哪些不能讓**、
**簽約前和開工前各要做什麼**、**參考來源**。
三個月後對方來議價，你要拿得出理由，而那時候客戶版上不會有。

## 三、留白要明寫

計劃書階段還沒談定的項目（信箱、人名、費用、範圍）**可以留白，但要列成一節**，
寫明「未經議定並書面確認前不構成承諾」，並在前言指過去。

留白與漏寫的差別就在這一節。沒有它，對方簽下去可以主張你默認了。

## 四、輸出 PDF

```
node .claude/skills/client-docs/md2pdf.mjs <in.md> <out.pdf>
```

零相依，用這台機器上的 Chrome（`Page.printToPDF`）＋系統的微軟正黑體。
A4、頁尾有頁碼、`⚠️` 開頭的引言自動變琥珀色提示框、其餘引言是灰色附註。

**不要用 Python 的 reportlab**（2026-09-22 起這台機器真的有 Python 3.13 了，
但這一條照舊）：reportlab 的內建字型沒有中文，要自己找一支 CJK 字型檔註冊進去，
而 Chrome 這條路直接用系統的微軟正黑體，還順便支援表格與分頁控制。

**驗收要用看的**，跟這個專案其他東西一樣：

```
SHOT=<scratchpad>/doc.png node .claude/skills/client-docs/md2pdf.mjs in.md out.pdf
```

會另外切成幾張長圖，讀圖確認三件事：中文沒變方塊、表格沒撐出頁面、
該是提示框的是琥珀色。只檢查「檔案產出來了」會漏掉字型掉回替代字這種錯。

## 五、支援的 Markdown

標題、表格（儲存格裡可以寫 `<br>`）、`>` 引言、圍欄程式碼、`---`、
`**粗體**`、`` `code` ``、數字清單（條目之間可以空行，續行縮排兩格以上）。

**沒有巢狀清單**——`- ` 子項目會被併進上一個條目變成一長串。
要分項就寫成 `（a）（b）（c）` 或拆成表格。

## 六、寫之前先查一次外部範本

這類文件有現成的官方骨架，照著排比自己想省事，而且審查方就是拿那份對表。
已經查過的來源收在 `references/sla-sources.md`（含台灣官方 SLA 參考範本的
章節結構與時效範例）。寫別種文件（驗收、報價）時同樣先查一次再動筆。

## 七、md2pdf 踩過的坑

三個都會讓它看起來「卡住」或「產出上一份文件」：

- **殘留的 Chrome 會佔住連線埠。** `chrome.kill()` 只殺掉啟動的那一支，
  Chrome 起來之後會 re-exec，真正那一窩已經不是它的小孩了。跑幾次就堆出十幾個
  殘留行程，然後新的那一支綁不上連線埠 → 這支程式接到**上一次那一份文件**，
  或一路等到超時。`freePort()` 和收工時照 profile 目錄殺行程就是為這件事。
  看起來卡住的時候先 `Get-Process chrome | Measure-Object`。
- **不要用 CDP 的 `Browser.close`。** 它關掉瀏覽器之後那一則回應永遠不會回來，
  而程式在等它 —— top-level await 掛住，exit code 13，而 PDF 其實已經寫出來了。
- **`taskkill /T` 沒有用**（同第一點的理由）。要照 `--user-data-dir` 認人。
