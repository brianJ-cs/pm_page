為什麼原本會掉東西

  • upsert() 送的是 { id, data: 整包 plan } —— 存檔不是「改這個欄位」， 而是把整包檔期覆蓋上去。B 送出的那一份裡面，A 剛改的東西根本不存在。
  • 寫入時沒有版本檢查：沒有比對 updated_at、沒有 If-Match。誰後送誰贏。
  • 只有開機的 bootSync() 會 pullAll()。開著頁面的人永遠不會自動看到別人的改動。
  • 就算重新整理，if (currentPlan && r.id === currentPlan.id) return; 還會刻意跳過 正在開的那一個檔期 —— 那行本來是為了保護「手上正在編輯的物件不要被換掉」 （換掉會變成改到孤兒物件），副作用是別人的更新也一起被擋掉。 要做 ③ 即時同步，就得先正面解掉這一行。

建議的順序

  • 先做 ① + ④。把「安靜消失」變成「明確擋下」，再讓人在撞車前就先知道。 幾十行，不動資料表。
  • 再做 ②。你們的工作本來就照版位切乾淨了（一個版位一位 PM）， 所以這一步做完，真實的撞車機率基本歸零。
  • 最後才是 ③。體驗最好，但要先處理上面那行 return。
  • OT / CRDT（Google Docs 那一套）跳過。那要引入套件和自己的持久化模型， 直接殺掉「兩支單檔 HTML、瀏覽器打開就是完整程式」這件事 —— 為了一天發生不到一次的情境，代價不成比例。
